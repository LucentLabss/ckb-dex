# CKB DEX Status Report — UI/UX Pass & Local Environment

## Current Status

With matching and settlement now working end-to-end (see last week's report), this week's focus shifted to the trading UI itself: making the order lifecycle legible, adding a confirmation step before signing, visualizing the order book, and fixing places where the UI could show misleading data. Alongside that, the local dev environment (MongoDB) was fully diagnosed and documented after coming up stopped.

## Delivered / Integrated This Week

- **Order lifecycle is now visible end-to-end.** The Open Orders table has a real Status column instead of a single ad-hoc "Pending" tag — orders now show as Broadcasting → Open → Matched → Submitted → Filled/Cancelled/Invalid, mapped directly from the backend's real state machine, each with a hover explanation of what it means.
- **Buy/Sell now has a confirmation step.** Clicking Buy or Sell opens a review modal (pair, side, price, amount, total, and — for buy orders — a disclosure of the small network-fee reserve added on top) before anything is built and signed. Previously orders were signed and broadcast immediately on click with no review.
- **A depth chart was added to the order book panel.** Cumulative bid/ask depth is now visualized as a step-area chart above the existing price/amount rows, with a hover crosshair and tooltip. Colors were run through the project's palette validator rather than picked by eye — it flagged the app's bright green as unsuitable for a large fill area, so the chart reuses the app's own existing dim/bright convention (translucent wash for the area, full color only for the 2px line).
- **Fixed a second instance of the "fake data masks real state" bug.** Two weeks ago a similar bug was fixed on the WebSocket path; the same issue existed on the initial REST fetch and on first page load — a genuinely empty order book or trade list was silently replaced with unrelated demo fixture data, making "no orders yet," "still loading," and "demo mode" indistinguishable. All three now render as clearly distinct, honest states, with skeleton loaders during the first fetch.
- **Light/dark theme toggle.** The UI was dark-only with colors hardcoded for a dark surface. A persisted toggle was added in the header; the light theme's colors were independently checked against a white surface rather than reusing the dark palette as-is — the dark theme's green, in particular, fails minimum text contrast on light backgrounds and needed a separately-validated shade.
- **Responsive fix.** The Open Orders / History tables gained an extra column this week; they now scroll horizontally on narrow screens instead of overflowing the page.

## Ready to Use

- Everything from last week (placing, matching, and settling exact-match orders), plus:
- A confirm-before-submit step on every order.
- Full order-status visibility while an order is in flight, not just at rest or filled.
- A visual depth chart alongside the existing order book list.

## Local Environment Notes

MongoDB for local testing runs in Docker, not as a native service — worth documenting since it wasn't obvious from the repo alone:

- The correct container is named `ckb-dex-mongo` (image `mongo`), with port `27017` published to the host. A second, unrelated container (`naughty_curie`) also runs a MongoDB image but does not publish its port, so it cannot be reached by the backend even while running.
- `ckb-dex-mongo` had stopped (clean shutdown, not a crash) and needed `docker start ckb-dex-mongo` before the backend could connect.
- The backend's "demo mode" fallback (starting up even when MongoDB is unreachable) does not actually work in practice — the bot's poll loop has no awareness of it and fails every cycle with a Mongoose "before initial connection is complete" error until MongoDB is reachable and the backend is restarted. It should be treated as effectively non-functional for now, not a real degraded mode. Worth a look next: either make the bot loop skip cleanly while disconnected, or remove the fallback so a missing database fails loudly and immediately at startup instead of appearing to run.
